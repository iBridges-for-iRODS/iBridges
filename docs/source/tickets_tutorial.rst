Working with Tickets
====================

iRODS tickets provide a simple way to share data without granting permanent
permissions or creating user accounts.

A ticket is a short string generated by iRODS that grants access to a single
collection or data object. You can share that string with collaborators, who
can then use it to access the data that the ticket was created for.

Typical use cases include:

* Sharing a dataset with external collaborators.
* Publishing data for download through an anonymous account.
* Allowing uploads into a specific collection.
* Giving temporary access that automatically expires.

This tutorial demonstrates how to create and use tickets with iBridges, both
from the command line and from Python.

Creating a Ticket
-----------------

Suppose you have a collection:

.. code-block:: text

    /zone/home/research-project/shared-data

To create a read-only ticket:

.. code-block:: console

    $ ibridges ticket create irods:/zone/home/research-project/shared-data

Example output:

.. code-block:: text

    Created read ticket for /zone/home/research-project/shared-data: kpIwGA1UZN0LFnM

The generated string is the ticket that you can share with others.

Creating an Expiring Ticket
---------------------------

Tickets can optionally expire automatically.

For example, to make a ticket valid until 31 December 2026:

.. code-block:: console

    $ ibridges ticket create \
        irods:/zone/home/research-project/shared-data \
        --date 2026-12-31

Example output:

.. code-block:: text

    Created read ticket for /zone/home/research-project/shared-data: kpIwGA1UZN0LFnM
    Expires on 2026-12-31.

After the expiration date the ticket can no longer be used.

Creating a Write Ticket
-----------------------

By default, tickets grant read access.

To allow uploads or modifications, create a write ticket:

.. code-block:: console

    $ ibridges ticket create \
        irods:/zone/home/research-project/incoming \
        --mode write

Write tickets should be shared carefully, as they allow changes to the
target collection.

Listing Existing Tickets
------------------------

To view all tickets that belong to your account:

.. code-block:: console

    $ ibridges ticket list

Example output:

.. code-block:: text

    Ticket          | Type  | iRODS Path                            | Expires
    ----------------+-------+---------------------------------------+--------------------
    kpIwGA1UZN0LFnM | read  | /zone/home/research-project/shared-data | 2026-12-31 00:00:00
    Xr8sTq2LmB9aVwE | write | /zone/home/research-project/incoming    | never

This overview helps you keep track of active tickets and their expiration
dates. Tickets without an expiration date show ``never``.

Deleting a Ticket
-----------------

Once a ticket is no longer needed, it can be removed.

.. code-block:: console

    $ ibridges ticket delete kpIwGA1UZN0LFnM

Deleting the ticket immediately revokes access for future users of that
ticket. If the ticket does not exist, an error is shown.

How Recipients Use Tickets
--------------------------

The person receiving the ticket does not need to be the ticket owner.

In many installations, tickets are used together with an ``anonymous``
account. The recipient connects with that account and then supplies the
ticket to gain access to the shared data.

A supplied ticket is applied to the connection of one session. It is not
stored anywhere, so it only lasts as long as that session. This is why the
command line offers a special way of supplying tickets, described next.

Using Tickets from the Command Line
-----------------------------------

The recipient first needs an iRODS environment file for the anonymous
account, for example ``~/.irods/anonymous_env.json``:

.. code-block:: json

    {
        "irods_host": "irods.server.url",
        "irods_port": 1247,
        "irods_user_name": "anonymous",
        "irods_zone_name": "demoZone"
    }

Select this environment (see ``ibridges init`` and ``ibridges alias``) and
supply the ticket together with the path it was made for:

.. code-block:: console

    $ ibridges shell --with-ticket kpIwGA1UZN0LFnM /demoZone/home/research-project/shared-data

This opens the interactive iBridges shell with the ticket already supplied.

.. code-block:: text

    ibshell:shared-data> ls
    sub_collection  demo.json

You can work with the upload, download and meta commands.
Type ``quit`` to leave the shell. The ticket is then gone with the session.

.. note::

    A single ``ibridges`` command on the command line ends its session when it
    is done, and the ticket ends with it. Running ``ticket supply``
    and then ``ibridges ls`` in a separate command therefore does not work.
    First open the shell and then use ``ticket supply``, or use the shell command with
    the extra option ``--with-ticket``.

You can also supply a ticket from inside a running shell:

.. code-block:: text

    ibshell:home> ticket supply kpIwGA1UZN0LFnM /demoZone/home/research-project/shared-data

.. note::

    A ticket on a data object gives access to that object only, not to the
    parent collection. Listing the parent collection may show
    nothing, while downloading the object itself works.

Anonymous Sessions and SSL
--------------------------

An anonymous session only uses the SSL and encryption settings that are in
the environment file (keys starting with ``irods_ssl_``, ``irods_encryption_``
or ``irods_client_server_``) or that you pass explicitly. If there are none,
the session connects without SSL settings.

If your server requires SSL, add the settings to the environment file, for
example:

.. code-block:: json

    {
        "irods_host": "irods.server.nl",
        "irods_port": 1247,
        "irods_user_name": "anonymous",
        "irods_zone_name": "zone",
        "irods_client_server_policy": "CS_NEG_REQUIRE",
        "irods_encryption_algorithm": "AES-256-CBC",
        "irods_encryption_key_size": 32,
        "irods_encryption_num_hash_rounds": 16,
        "irods_encryption_salt_size": 8
    }

or pass them from Python with the ``anonymous_options`` argument, see below.

Using Tickets from Python
-------------------------

The :class:`~ibridges.tickets.TicketAccess` class supplies a ticket to a
session and provides convenient access to the shared path.

The example below connects as an anonymous user and accesses a ticketed
collection.

.. code-block:: python

    from ibridges import Session
    from ibridges.tickets import TicketAccess

    env = {
        "irods_user_name": "anonymous",
        "irods_host": "irods.server.nl",
        "irods_port": 1247,
        "irods_zone_name": "zone",
    }

    session = Session(env)

    access = TicketAccess(
        session,
        "kpIwGA1UZN0LFnM",
        irods_path="/zone/home/research-project/shared-data",
    )

The ticket is supplied to the session when the
:class:`~ibridges.tickets.TicketAccess` object is created.

If the server requires SSL and the environment does not contain the settings,
pass them when creating the session:

.. code-block:: python

    from ibridges.session import DEFAULT_ANONYMOUS_SSL_SETTINGS

    session = Session(
        env,
        anonymous_options={"ssl_settings": DEFAULT_ANONYMOUS_SSL_SETTINGS},
    )

Instead of an environment dictionary, you can also use an environment file
with :func:`~ibridges.authenticate.interactive_auth`. For anonymous users this
never asks for a password:

.. code-block:: python

    from ibridges.authenticate import interactive_auth

    session = interactive_auth(irods_env_path="~/.irods/anonymous_env.json")

Discovering the Shared Path
---------------------------

The ``irods_path`` argument is optional. If you leave it out, iBridges tries to
look up the path that belongs to the ticket on the server:

.. code-block:: python

    access = TicketAccess(session, "kpIwGA1UZN0LFnM")
    access.path

Example result:

.. code-block:: text

    /zone/home/research-project/shared-data

The returned path is the collection or data object that was shared by the
ticket owner. This lookup does not work on every server or for every user.
If it fails, a ``ValueError`` is raised and you need to supply ``irods_path``
yourself, so the safest option is to ask the ticket owner for the path together
with the ticket string.

Listing Shared Data
-------------------

Once the path is known, the data can be accessed normally.

For example:

.. code-block:: python

    path = access.path

    if path.collection_exists():
        for item in path.walk(depth=1):
            print(item)

Downloading Data
----------------

After a ticket has been supplied, data objects and collections can be read and
downloaded through the same session.

.. code-block:: python

    from ibridges import download

    download(session, access.path, "~/Downloads")

From the user's perspective, the ticket behaves like a temporary permission
grant limited to the shared location.

Important Notes
---------------

Tickets are stored on the iRODS server rather than in iBridges.

A few important points to remember:

* Tickets grant access to a single collection or data object.
* Tickets may be read or write tickets.
* Tickets can optionally expire automatically.
* Ticket owners do not need to supply their own tickets. Use
  ``TicketAccess(session, ticket, supply=False)`` if you do want to use the
  class as the owner.
* Deleting a ticket revokes future access.
* A supplied ticket stays applied to the session, also after the ticket has
  been deleted. Further operations on that session then fail with
  ``CAT_TICKET_INVALID``.
* Tickets should therefore only be used on a dedicated session, such as an
  anonymous session, and that session should not be reused for unrelated work.
* Do not delete a ticket while a shell or session is still using it.
* On the command line a supplied ticket only lasts for the shell that
  ``ibridges ticket supply`` opens.

Summary
-------

Tickets are an easy way to share iRODS data without modifying user
permissions.

The typical workflow is:

1. Create a ticket with ``ibridges ticket create``.
2. Share the ticket string and the path with collaborators.
3. The collaborator supplies the ticket, with ``ibridges ticket supply`` or
   with :class:`~ibridges.tickets.TicketAccess` in Python.
4. The collaborator accesses the shared collection or data object.
5. The ticket expires or is deleted with ``ibridges ticket delete`` when access
   is no longer required.
